## 0.6.0

### Minor Changes

- [#2899](https://github.com/stella/folio/pull/2899) [`a3f57ed`](https://github.com/stella/folio/commit/a3f57edb7bea07ebb3b39bd4f32227c9daa2172d) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio fill` (MCP `fill_template`) builds a document from a template and Markdown or block-list content in one direct write: it keeps the template's sections, headers, footers, front matter and an optional trailing block, styles the content through a map to the template's paragraph styles and numbering, and fills `{{name}}` fields and exact-text replacements in every story. String flags a command declares read `@file`.

- [#2898](https://github.com/stella/folio/pull/2898) [`6d33d26`](https://github.com/stella/folio/commit/6d33d26de9a028095a13ef6681cba8c186a8a6a3) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio literal-numbering` (MCP `numbering`) writes list labels as literal text, displayed or counted continuously in a house-style format such as `[{n}.]`, and removes list membership while keeping the level's indentation, tab stops and label formatting; `folio apply-numbering` puts paragraphs back into a numbering instance, stripping a leading literal label.

- [#2897](https://github.com/stella/folio/pull/2897) [`32097b7`](https://github.com/stella/folio/commit/32097b7dd3394b4f4fb5c4a1e3fb7858d567440e) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio placeholders` (MCP `placeholders`) lists the placeholders left in every story (`[•]`, `[…]`, `{{name}}`, `[[name]]`, `TODO`, or `--pattern`s) with block ids and context, fills them from `--fill` values as tracked changes or with `--direct`, and exits with the new code 11 while any remain. JSON flags also read `@file.json`.

- [#2896](https://github.com/stella/folio/pull/2896) [`612e2fc`](https://github.com/stella/folio/commit/612e2fc757cc79301d0ed358b606464907c70d13) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio lang` (MCP `proofing_language`) reports the `w:lang` languages each part states and, with `--set`, writes a proofing language into the `w:docDefaults` run properties, the default paragraph style, every stated style language, and `w:themeFontLang`; `--runs` also sets every language a run states.

- [#2900](https://github.com/stella/folio/pull/2900) [`a7d1477`](https://github.com/stella/folio/commit/a7d1477dd52ee97b09c9e901e8b32335e2f148de) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio render` takes `--pages` (numbers and ranges such as `1-3,5`) and `--format pdf|png|html`, and writes one PNG per page when `-o` contains `{page}`, all from one headless Chromium session.

- [#2895](https://github.com/stella/folio/pull/2895) [`ef6c226`](https://github.com/stella/folio/commit/ef6c22603866dd847e24fbceb9ce0a20237876ab) Thanks [@jan-kubica](https://github.com/jan-kubica)! - `folio sanitize` (MCP `sanitize_document`) removes comments with their companion parts, anchors, and comment-only `people.xml` entries, every `w:rsid*` attribute and the settings `w:rsids` table, and on request the identifying document properties; without a destination it reports what it would remove.

- [#3146](https://github.com/stella/folio/pull/3146) [`d29dc0c`](https://github.com/stella/folio/commit/d29dc0ccd9b044f6dd33022fd3e9e0231239ef28) Thanks [@jan-kubica](https://github.com/jan-kubica)! - The legacy engine no longer opens a package whose XML names an undeclared entity (`&nbsp;`, `&copy;` or any name but XML's five built-ins); it used to read common HTML names as their characters and keep other names as written. Both engines now refuse such a package with `UndeclaredXmlEntityError`, which names the part, the reference's offset and the entity. Character references are read as before. The CLI's save check refuses such a part as not well-formed.

- [#3267](https://github.com/stella/folio/pull/3267) [`04a2eea`](https://github.com/stella/folio/commit/04a2eea423d5ee264d855bc9665efdd8e9649007) Thanks [@jan-kubica](https://github.com/jan-kubica)! - A part holding a reference XML refuses is not opened and does not validate: an entity no declaration defines, or a character reference to a character XML 1.0 does not allow (`&#0;`, `&#x1;`, `&#xFFFE;`, a surrogate, past U+10FFFF), with digits that are not a number (`&#12ab;`), or with a hexadecimal marker in capitals (`&#X41;`). Both engines refuse it with `MalformedXmlReferenceError` (part, offset, reference and kind), which replaces `UndeclaredXmlEntityError`; `malformedXmlReferenceError` replaces `undeclaredXmlEntityError`. The legacy engine no longer reads such a reference as nothing. The package validators and the CLI's save checks refuse the same parts. `XmlReadOptions.undeclaredEntities` and `XmlUndeclaredEntities` are removed; no read accepts these references.

- [#2616](https://github.com/stella/folio/pull/2616) [`4fdd329`](https://github.com/stella/folio/commit/4fdd32901ffd192e9031015e9783d26066ab6072) Thanks [@jan-kubica](https://github.com/jan-kubica)! - The VS Code extension's editor runs the canonical engine.   Redline insertions import their referenced style closure and numbering through collision-safe resource owners while preserving stated inheritance. An unimportable resource closure raises GenerateRedlineDocxResourceImportError before any body operation, preserving the base document.

  Source-undefined style references stay verbatim when also undefined in the base. Dangling numbering remains normalized to none by the existing parser, so inserted paragraphs stay unnumbered through save/reopen.

  Breaking: undefinedStyles is replaced by the required undefinedReferences option, with no default or alias. Every execution caller must pass { undefinedReferences: "refuse" } for editing or { undefinedReferences: "keep" } for comparison/redline. Both reviewer methods and React/Vue operation refs require an explicit policy, applying it to style and numbering references alike.

## 0.1.0

### Minor Changes

- [#1058](https://github.com/stella/folio/pull/1058) [`3bb6ac0`](https://github.com/stella/folio/commit/3bb6ac008d9c0b0092e6f7a39748b1ce1d3fb5cd) Thanks [@jan-kubica](https://github.com/jan-kubica)! - Add `folio mcp`, a stdio MCP server over the same tool registry: each tool takes its folio-agents arguments plus a file envelope (`path`, `fileVersion` required on changes, `destination`, `overwrite`, `txId`, `allowRepack`, `mode`), every path must resolve inside an allowed `--root`, reads are bounded by block count, match count, and response size with version-bound cursors, and the operation schema and server rules are served as resources.

- [#1056](https://github.com/stella/folio/pull/1056) [`c9776b0`](https://github.com/stella/folio/commit/c9776b0694d2193d307999b788e1b72fb3aae80b) Thanks [@jan-kubica](https://github.com/jan-kubica)! - Add `@stll/folio-cli`, the `folio` command line over the folio-agents tools for `.docx` files on disk. This release reads: `read`, `outline`, `section`, `stories`, `story`, `find`, `comments`, and `changes`, with flags generated from each tool's schema, a `{ ok, data | error }` envelope, SHA-256 `fileVersion` preconditions, labelled synthetic block ids, and version-bound read cursors.

- [#1062](https://github.com/stella/folio/pull/1062) [`53f76ba`](https://github.com/stella/folio/commit/53f76ba8d0ae866d060dc68b15f19346e41ac14a) Thanks [@jan-kubica](https://github.com/jan-kubica)! - Add `folio render <file> -o <out.pdf|out.png|out.html> [--page n]`, which paints the document with folio's own layout and PDF or DOM backend (PNG through an optional `playwright-core` Chromium), and `folio serve <file> [--port n]`, a read-only live preview on 127.0.0.1 behind a random token that re-renders when the file's version changes.

- [#1057](https://github.com/stella/folio/pull/1057) [`1473902`](https://github.com/stella/folio/commit/1473902334d44918f4287bf0deef51da89ba0073) Thanks [@jan-kubica](https://github.com/jan-kubica)! - Add the `folio` write commands: `suggest`, `comment`, `reply`, `resolve`, `accept`, `reject`, and `compare -o`. Each change is one transaction: `--in-place` or `-o` onto a plain `.docx` (replacing an existing file needs `--overwrite` and its version), a required `--expect-version` (waived only by `--no-expect-version`) re-checked under a fenced cooperative write lease (`locked`, exit 10, unless `--force`), a backup of whatever is replaced, a staged and validated package renamed into place, selective saves unless `--allow-repack`, author from `--author`/`FOLIO_AUTHOR`/git with no default, one `--date`-overridable timestamp, a `.folio/journal.jsonl` line, `--tx-id` replay, and checked recovery of a stage a crash left behind. Sidecar files are never used through symlinks or hard links.
